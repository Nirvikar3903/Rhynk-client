# Convert Google Stitch HTML Workflow

Recurring task: the user pastes a full HTML page generated by Google Stitch
(Tailwind CDN + inline `tailwind.config` + Material Symbols + vanilla JS) and
it needs converting into React matching this repo's actual conventions —
not a literal port of the markup/classes.

## Structural mapping

One pasted HTML file → three files, same split already established for
signup (`src/pages/auth/SignUpPage.jsx` → `src/features/containers/auth/SignUpContainer.jsx`
→ `src/components/auth/SignUpForm.jsx`):

- `pages/<domain>/<Name>Page.jsx` — route-level, composes a layout + one container, no logic (see [[create-page]]).
- `features/containers/<domain>/<Name>Container.jsx` — owns local state (`useState` — no form library installed, see [[create-form]]) and, once wired to real APIs, RTK Query hooks (see [[create-api-service]]).
- `components/<domain>/<Name>Form.jsx` (or similarly named dumb component) — the actual visual layout, props-only, no state/fetching (see [[create-component]]).
- Reuse an existing layout (`layouts/AuthLayout.jsx`) if the mock is the same category of screen (auth, onboarding); only add a new layout file for a genuinely new screen category.

## Styling mapping — never keep Tailwind

The pasted HTML always includes a Tailwind CDN `<script>` + a `tailwind.config` block + utility classes. None of it is kept — see [[04-ui-styling]]. Translate:

| Stitch/Tailwind | Rhynk/MUI |
|---|---|
| Tailwind color tokens in `tailwind.config` (`primary`, `surface`, `on-surface`, …) | `theme.palette.*` / `theme.palette.custom.*` — match by *intent* (Stitch's `primary` → our `primary.main` = `#5B4FE9`; its `surface`/`background` → `background.default`/`background.paper`), not by copying the hex values, since Rhynk's palette (`src/theme/index.js`) is already the source of truth |
| `rounded-lg`/`rounded-xl`/border-radius scale in `tailwind.config` | `theme.shape.borderRadius` (12 globally) or an explicit `borderRadius` in `sx` for one-off cases (e.g. the 8px button override already in `getCommonThemeConfig`) |
| `tailwind.config` spacing scale (`md: 12px`, `xl: 24px`, …) | `theme.spacing()` / MUI's numeric `sx` spacing (`p: 2` = 16px under our 4px-multiple scale — see [[04-ui-styling]] and `theme/index.js`'s `spacing: (factor) => \`${factor * 4}px\`) |
| `font-*`/`text-*` custom scale in `tailwind.config` | `typography` variants already defined in `getCommonThemeConfig()` (`h1`, `h2`, `subtitle1`, `body1`, `body2`, `caption`) — add a new named variant only if none of the existing ones fit, don't invent ad hoc `sx={{ fontSize: '13px' }}` for something a variant already covers |
| Utility classes on JSX elements (`className="flex items-center gap-2"`) | MUI's `sx` prop on the matching component (`Box`, `Stack`, etc.) — see [[04-ui-styling]] |
| Inline `<style>` block / `@keyframes` | Prefer `framer-motion` (`motion.div` + `animate`/`variants`) for anything that's actually an animation; plain `sx` keyframes only for something trivial that doesn't need JS-driven control |

## Background

Every Stitch mock re-generates its own inline SVG `<pattern>` "doodle"
background. Don't copy it — use the existing
`components/common/DoodleBackground.jsx`, which already reads
`theme.palette.custom.doodle.{color,opacity}` (see [[04-ui-styling]],
`src/theme/index.js`). If a screen category needs a different motif emphasis
(e.g. Music Room leaning on waveforms per `DESIGN.md`), extend that one
component with a `variant` prop rather than forking a second background
component.

## Icons

- Stitch mocks use Google's Material Symbols font (`<span class="material-symbols-outlined">mic</span>`). Map each one to the equivalent `@mui/icons-material` import (e.g. `mic` → `MicIcon`, `graphic_eq` → `GraphicEqIcon`, `visibility`/`visibility_off` → `VisibilityIcon`/`VisibilityOffIcon`) — see [[04-ui-styling]]. Don't add the Material Symbols web font or keep `<span class="material-symbols-outlined">`.
- For brand marks needing exact multi-color reproduction (Google "G" logo, etc.) that have no MUI equivalent, inline the SVG as a small local component in the same file — the `GoogleIcon` const in `SignUpForm.jsx` is the precedent.
- `src/assets/` is for genuine static bundled graphics (illustrations, photos) that don't need to pick up theme color dynamically. There's no SVGR/`vite-plugin-svgr` installed, so a plain `.svg` import resolves to a URL string, not a component — fine for an `<img src>` or CSS `background-image`, not for a themed icon. If a screen needs many themed custom icons as separate files (not just one or two inlined), that's a `vite-plugin-svgr` dependency decision to raise first, not something to add ad hoc.

## Motion

`framer-motion` is installed — use it for entrance transitions, hover/tap
micro-interactions, and anything the mock implies with a CSS animation
(e.g. a pulsing waveform, a slide-in card) instead of hand-rolled
`@keyframes`. Don't add it to a screen that has no actual motion in the
source mock just because it's available.

## Contract mismatches — build first, flag after

Stitch mocks are pure visual designs and routinely don't match the
documented backend contracts (see [[06-auth-security]] for auth specifically)
— e.g. the signup mock's Phone/Email toggle with no username field, when
`POST /auth/register` only accepts `{ username, email, password }`. Per
standing instruction: build the screen to match the visual design, leave
submission wired to a stub/toast (not a real mutation) where the fields
don't line up, and call out the specific mismatch in the response after
building — don't stop to ask per screen, and don't silently invent fields or
endpoints to paper over the gap. Real API/schema wiring happens once the
user provides it (after the current batch of screens).

## Checklist

- [ ] No Tailwind CDN script, `tailwind.config` block, or `className` utility strings survive into the React output.
- [ ] No Material Symbols web font — every icon is `@mui/icons-material` or an inlined SVG component.
- [ ] Background uses `components/common/DoodleBackground.jsx`, not a re-copied inline `<pattern>`.
- [ ] Follows Page → Container → Component, matching the signup precedent.
- [ ] Contract mismatches (if any) are called out in the response, not silently resolved either direction.
